# 共識 Accord — 公司內部投票系統第一版

本機可操作版本，使用原生 HTML / CSS / JavaScript 與 Python 標準庫 API、SQLite。獨立專案，沒有複製交通系統的員工資料、部署識別或憑證。

## 啟動

在此目錄執行 `python3 server.py`，瀏覽 http://127.0.0.1:8876 。Python 3.9 以上，無須安裝套件。可用 `PORT` 指定其他埠、`VOTE_DB` 指定資料庫位置。

也可以在 macOS 雙擊「啟動投票系統.command」。保持終端機開啟；停止時按 Control+C。

## 已實作

- 介面只分管理端與同仁端，右上角直接切換。可使用 /#admin 或 /#employee 直接進入；不同部門共用同一個同仁端，活動依指定對象顯示。只有管理員可建立活動。
- 四步驟建立：主題與日期、對象與投票方式（含匿名設定）、文字／圖片選項、預覽與確認發布。
- 各選項可另外指定開放部門，限於活動對象內；只影響單一選項。API 會過濾不適用的選項並拒絕越權投票，發布前檢查每位參與者都有選項。
- 限定選項的比例以有資格選此項且已投票的人數為分母，管理員可查看各項可投及已投人數。
- 單選／複選與上限；匿名／記名；全體、部門、工號或姓名搜尋指定人員。
- 每一步固定位置可儲存未完成草稿；離開時可儲存／放棄／繼續編輯。「建立投票」提供新投票與草稿清單，重開草稿回到原步驟。瀏覽器關閉／重新整理使用原生離開提醒，且在同一分頁保存本機恢復暫存。草稿以 revision 防止舊視窗覆寫。發布後內容鎖定，錯誤活動可取消並保留紀錄。
- 點選即標記，右下角確定投票，提示不可修改後再次確認；API 成功才顯示成功。
- SQLite 唯一限制與交易防止重複投票；伺服器驗證資格、期間、選項與上限。
- 同仁投完才看結果；管理員隨時查看即時統計、投票率及參與名單。
- 長條圖顯示票數與比例，以有資格選擇該項且已投票的人數為分母；複選各項比例加總可能超過 100%。畫面每 5 秒更新。
- 匿名活動只存參與憑據及選項累計，不儲存個人選擇；記名活動保存對應。
- 活動自動依時間開始及結束，歷史結果保留。管理操作及投票參與歷程有處理人與時間。
- SQLite 存於 `data/votes.sqlite3`，重新啟動保留。活動預設為空白，不會自動建立示範活動。

## 目前界線

此版只綁定本機 127.0.0.1。示範身分透過 X-Demo-User 切換，不是正式驗證，請勿對外提供或放入真實公司表決資料。已提供主網站登入與名冊串接接口，但尚未連接實際主網站，正式使用前仍需設定 host 模式、獨立資料庫與備份。此儲存庫不含正式部署。未投票者於截止後仍不能查看票數，依「投完才可看票數」規則。

前端與 API 分開，之後可按正式部署決策移植到 Worker／D1。這版 SQLite API 供本機流程驗收。

## 驗證

`python3 -m unittest discover -s tests -v`

`node --test tests/frontend.cjs`

送出使用操作識別鍵防止網路重試造成重複活動或票數，成功狀態直接採用儲存回應，不依賴再次抓取列表。

## 主網站串接

已提供可啟用的 host 模式與登入／名冊接口，規格見 [INTEGRATION.md](INTEGRATION.md)，主網站伺服器範例見 `examples/host-adapter.mjs`。目前測試入口仍使用 demo 模式；主網站技術、網址與帳號來源尚未提供，尚未完成實際連線。

## 儲存庫與資料範圍

GitHub：`Redball-siri/accord-vote`。儲存庫只保存程式、虛構帳號、設定範例、串接文件與測試。投票資料庫、實際名冊、密鑰、本機截圖及固定結算預覽不會納入 Git。

GitHub Actions 會在推送與 Pull Request 時執行 API、主網站串接、前端行為與 JavaScript 語法檢查。此專案目前沒有自動部署流程。
